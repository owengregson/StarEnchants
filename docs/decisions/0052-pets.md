# ADR 0052: Pets — a leveling head-item content family on the shared engine

- **Status:** Accepted
- **Date:** 2026-07-11
- **Deciders:** project owner + agent
- **Extends:** ADR-0014 (content compiler), ADR-0039 (source-erased `Ability`), ADR-0047
  (feature-module wiring), ADR-0048 (use-items — the right-click cold path this family rides)
- **Relates to:** ADR-0035 (live per-wearer resolver inputs), ADR-0040 (render-from-state),
  ADR-0041 (apply gestures — pet food), ADR-0044 (era seams — textured heads), ADR-0050 R4
  (cooldown scopes)

## Context

A pet is a textured player-head item that carries a mutable LEVEL and levels up from mob
kills, vanilla XP gain, time held, and a drag-applied Pet Food item. A PASSIVE pet's
abilities run while the head sits anywhere in the hotbar; an ACTIVE pet fires on
right-click with a per-pet cooldown, and some grant a timed buff window. Ability strength
(and sometimes the cooldown) scales with level in authored brackets. Building this as a
bespoke feature would re-implement suppression, cooldowns, conditions, chance, passive
potion maintenance and repeating timers — the drift ADR-0039's erasure exists to prevent.

## Decision

1. **A new content family `content/pets/*.yml`** — the 5th `LibraryLoader` loop. Filename
   stem = the pet key. Each file declares likeness identity (`display`, `color`, `head`
   base64, optional `material` fallback), `type: ACTIVE|PASSIVE`, `description`, and a
   sparse **`levels:` bracket map**: each key is a level FLOOR; the highest floor ≤ the
   item's level is the live bracket. A bracket carries `cooldown`, `duration` (the ACTIVE
   armed window), and `abilities:` in the crystal/use-item dual form. Brackets lower to
   stable keys `pet:<key>/<floor>[/aN]` — per-bracket abilities are per-level enchant
   definitions in all but name, so the engine needs no level-scaling primitive.

2. **Pets are the SIXTH `WornState` source.** `WornResolver` scans the player's hotbar for
   pet-codec items and resolves the current bracket's ability ids into the same flattened
   arrays every other source uses (bracket floors come from a live library supplier, the
   ADR-0035 pattern). PASSIVE pets contribute all bracket abilities while in the hotbar —
   `PASSIVE` potions are maintained by the existing `PassiveEffectDriver`, `REPEATING`
   abilities by the existing `RepeatingDriver`, with zero new engine machinery. An ACTIVE
   pet's non-`USE` abilities are contributed **only while armed** (a live armed-window
   supplier, see 4). Hotbar mutations request the standard `EquipListener.refresh`.

3. **Right-click rides the ADR-0048 cold path.** The pet listener resolves the bracket and
   calls `TriggerDispatch.fireUse` with the bracket's `USE` stable keys — full gate
   sequence, gate-6 cooldown on the bracket stable key (its own scope id; never the
   enchant/group scopes, ADR-0050 R4), `UseAttempt` collapse. Authored `trigger:` on an
   ACTIVE pet's first ability is warned and forced to `USE` (W_LOAD_PET_TRIGGER), like
   use-items. No new trigger is added; the 32-bit trigger budget is untouched.

4. **Timed buffs = an armed window, not a new effect model.** Activation arms
   `(player, petKey)` in a `PetArmedStore` until `now + duration`, requests a worn
   refresh (the armed ATTACK/DEFENSE abilities appear in `WornState`), and schedules the
   expiry on the player's entity scheduler: clear + refresh + the universal ENDED message.
   Death/quit clears the window. Shield/Enderman/Eagle/Anubis are plain per-hit abilities
   (`DAMAGE_MOD`, `STRIP_SCROLL`) that only exist in the walk while armed.

5. **Level + exp live on the item, outside the combat blob.** `PetCodec` stores
   `pet` (key), `petlevel`, `petexp` as separate PDC entries (the trak rule: frequent
   counters never thrash the `ItemView` cache). Leveling listeners follow the soul/trak
   precedents: mob kills via `EntityDeathEvent` MONITOR + `Scheduling.onEntity(killer)` hop
   (simple `getKiller` attribution, deposit-on-any-kill precedent; no spawner filtering —
   matches souls), vanilla XP via a dedicated `PlayerExpChangeEvent` MONITOR listener
   (post-`EXP_MULTIPLY` amount × knob), passive time via the per-minute pets sweep, and Pet
   Food via an ADR-0041 `ApplyGestureListener` leaf (+N levels baked into the food's PDC at
   mint, clamped to the universal max; check-before-consume). Pet name/lore re-render from
   state on level change only (a pet head is a carrier-class item, not gear — direct
   recompose from the universal template, the book-likeness exemption).

6. **Universal likeness + universal messages.** `items/pet.yml` is the one likeness for
   every pet (enchant-book precedent): shared `name`, `lore-active` / `lore-passive`
   templates ({COLOR}/{NAME}/{TYPE_TAG}/{DESCRIPTION}/{TIME_FORMATTED}/{USAGE} tokens) and a
   single-sourced `level-line` ({LEVEL}/{MAX_LEVEL}/{EXP}/{EXP_NEXT}). `items/pet-food.yml`
   is the dust-precedent apply item (`levels` knob, {AMOUNT} token). The three universal
   messages (ability-activated / ability-ended / on-cooldown with {TIME_FORMATTED}) are
   config templates in the master config `pets:` section (the `message-on-activate`
   precedent, with an `uppercase` knob), rendered prefix-free.

7. **New engine surface** (all fingerprint-drifting; goldens regenerated):
   - `TEMP_BLOCK` gains shape `BOX` (width/height/depth fill, `airOnly` respected) — the
     Spider webs are pure YAML on the existing ledger.
   - `CAGE` (new kind): safe-checks a 5×6×5 volume at midpoint(actor, victim)+2y, places a
     stone-brick floor/roof + iron-bars ring around a 3×4×3 air interior through the
     `TempBlockLedger` (per-tile region re-key), and teleports both parties to opposite
     interior cells facing each other. The spec diagram's outer-3×3 reading leaves a 1×1
     interior that cannot hold two displaced players, so 3×4×3 names the INTERIOR.
   - `STRIP_SCROLL` (new kind): removes a White/Holy-White protection marker from one
     random protected piece of the victim's armor/held item on the victim's own region
     thread (`Affinity.TARGET_ENTITY`), via a `GearProtection` seam wired at the
     composition root (the engine never touches the item codecs directly).
   - `MODIFY_MONEY` gains mode `interest_percent` — deposit the target a fraction of their
     OWN balance, capped live by the master-config `pets.max-percent-money-cap` supplied
     through `SinkEnv` (0 = uncapped). The Fish pet is `REPEATING` + this mode.
   - `SPAWN_ENTITY` gains summon flags: `powered`, `ai`, `targeting`, `mount:
     none|activator`, `saddled`, `detonate: none|player-hit`. Tracked summons register in a
     static UUID registry (the `GuardianCasts` pattern — no entity PDC, 1.8-safe); feature
     listeners cancel targeting, gate the creeper's detonation on a player hit, and clean
     up on disable. "Invincible" summons ship as spawn health 1024 (hittable, knockback
     intact) rather than `setInvulnerable` (which would suppress the hit events).
   - Condition fact `actor.belowvictim` — NUMERIC: how many blocks the actor's feet sit below the
     victim's (negative = above), so the Eagle's threshold is authored on its condition
     (`%actor.belowvictim% > 1.5`), never hardcoded in the engine.

8. **Textured heads are an ADR-0044 era seam.** `item.head.TexturedHeads` (NONE default)
   with `ModernTexturedHeads` (Paper `PlayerProfile` + `ProfileProperty` +
   `SkullMeta#setPlayerProfile`, probed once — API-surface only, mapping-flip immune;
   never `complete()`) and `LegacyTexturedHeads` (`SKULL_ITEM:3` + authlib `GameProfile`
   reflection), bound in both `EraBindings`, installed into `ItemFactory` as an injected
   applier (the `customItemResolver` idiom). Legacy material aliases added:
   IRON_BARS↔IRON_FENCE, COBWEB↔WEB, STONE_BRICKS↔SMOOTH_BRICK; SKELETON_HORSE degrades
   per §6 of the codeshare design (legacy spawns a skeleton-variant Horse via the era leaf).

9. **One `PetsModule`** (ADR-0047): LIVE toggle `features.pets`, listeners (use, leveling,
   food gesture, hotbar refresh, summon guards), the per-minute sweep boot, `PetArmedStore`
   + cooldown state as `PlayerScoped` stores, `Mints.pet`/`Mints.petFood` (give + tiles),
   pets browser + admin level-drill menus with hub/console tiles, lang roots, disable stops.

## Consequences

- Adding a pet is PURE YAML, gated by `CatalogValidationTest`/`CosmicPackValidationTest`.
- New kinds/params/fact drift the ADR-0046 fingerprint + docs goldens (`./gradlew
  regenDocs`) and the wiring goldens (`RegistryWiringTest`, module count).
- The hotbar scan adds inventory-event refresh requests (debounced; the existing 40-tick
  sweep is the safety net) — no per-hit cost anywhere: armed windows resolve at refresh
  time, never in the gate walk.
- Fish income no-ops without an economy provider and on the 1.8.9 lane (no Vault bridge
  there — recorded degrade). Imagegen menu previews show untextured heads (cosmetic).
- Cooldowns burn on activation even when a world-effect later aborts (e.g. an unsafe cage
  volume); authored conditions (`%nearbyenemies%`) keep the common no-target case free.
